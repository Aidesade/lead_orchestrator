# Веб-интерфейс лидген-оркестратора

Фронт (React + Vite) поверх FastAPI-обвязки над `lead_orchestrator/orchestrator.py`.
Умеет: запускать прогоны, показывать живой прогресс, вести таблицу лидов и карточку компании.

```
web/
  api/     FastAPI: спавн оркестратора, разбор его stdout в события, SSE, чтение лидов
  ui/      React + Vite SPA
```

## Запуск

Бэкенд поднимать ТЕМ ЖЕ Python, которым запускается оркестратор (`py`): API спавнит
`orchestrator.py` через `sys.executable`, и в нём должны быть зависимости пайплайна.

```bash
# 1) API (из корня репозитория D:\lead_gen)
py -m pip install -r web/api/requirements.txt      # fastapi + uvicorn, если ещё нет
py -m uvicorn web.api.main:app --port 8000

# 2) Фронт
cd web/ui
npm install
npm run dev          # dev: http://localhost:5173, /api проксируется на :8000
npm run build        # прод: dist/ — его начинает раздавать сам FastAPI на :8000
```

После `npm run build` весь интерфейс живёт по адресу `http://127.0.0.1:8000` — отдельный
Node-процесс в проде не нужен.

## Как это устроено

**Оркестратор — только CLI, библиотечного API у него нет.** `main()` делает argparse,
глобально подменяет `sys.stdout`/`sys.stderr` на `_Tee` и зовёт `sys.exit`. Импортировать
его в веб-процесс нельзя — он заберёт себе stdout и уронит воркер через `SystemExit`.
Поэтому API **спавнит его подпроцессом** (ровно как `orchestrator_agent.py` и Dockerfile),
читает stdout построчно и превращает строки в события (`api/events.py`).

Структурированных событий у оркестратора нет — он печатает русский текст. Но префиксы
стабильны, а `_Tee` флашит каждую строку, так что стрим работает. Парсер проверен на
**настоящих логах** прошлых прогонов:

```bash
py web/api/test_events.py            # прогоняет D:\orq_tmp\run_*.log через парсер
# run_night.log: 379/382 строк распознано, 26/26 компаний, стадии и стоимость сходятся
```

Если однажды в оркестратор добавят `--json-events`, парсер станет тонким фолбэком:
все точки печати собраны в `orchestrator.py` и `deep_research_engine._note`.

## Решения, которые важно не сломать

**Один активный прогон.** Второй запуск получает `409`, а не встаёт в очередь. Параллельные
прогоны в этом пайплайне не безопасны и нигде не залочены: два сбора дерутся за один
`--user-data-dir` Chrome, дефолтный путь лидов детерминирован (`leads_<отрасли>.json`) и
перезаписывается, а `_flush_outbox()` на старте прогона B дольёт файлы прогона A прямо
посреди его работы.

**Объём задаётся через `--per-industry`, а не `--count`.** Оркестратор делит `--count` как
`ceil(count/K)` по отраслям, и «10 компаний по трём отраслям» молча превращалось в 4 на
отрасль. Форма считает и показывает итог: `N × число отраслей`.

**Модель писателя.** Выпадашка «Модель» — это флаг `--model` (писатель двух .docx):
`kimi` (по умолчанию), `opus`, `sonnet`. `kimi` — псевдоним: реальное имя модели берётся
из `KIMI_WRITER_MODEL`/`KIMI_MODEL_NAME` (дефолт `kimi-k2.7-code`). Список отдаёт
`/api/models`, а не фронт — чтобы в UI нельзя было выбрать модель, которой пайплайн не умеет.
На Kimi вилка «$N–$2N» не показывается: она верна только для Claude-сессий, а цену за вызов
шлюз Kimi наружу не отдаёт (в итоге прогона будет `$0` — это не баг).

**Несколько регионов и исключения — это ОДИН `--region`.** Коллектор сам разбирает строку
(`source_rusprofile.parse_region_query`): запятая = перечисление, приставка «не » = исключение,
аббревиатуры (ХМАО/ЯНАО/СПб) разворачиваются по `REGION_ALIASES`. Строку собирает бэкенд
(`build_argv`), а не фронт — синтаксис это деталь CLI. Подсказки отдаёт `/api/regions`, и
токен в подсказке подобран так, чтобы матчиться ПОДСТРОКОЙ по выдаче RusProfile («Татарстан»
⊂ «Республика Татарстан»); фильтр по региону там клиентский, сервер ключ `region` не принимает.
Готча из коллектора: «Москва» во ВКЛЮЧЕНИИ матчит и «Московскую область», а в ИСКЛЮЧЕНИИ
области не задеваются — это поведение `region_included`/`region_excluded`, оно вынесено
подсказкой в UI.

**Проверка сессии RusProfile — только по кнопке.** Она поднимает настоящий Chrome на том же
профиле, что и фаза 1, поэтому не делается автоматически при заходе на страницу и запрещена
во время прогона (иначе два Chrome дерутся за один профиль). Логин по-прежнему ручной:
`py rusprofile_session.py --login`.

**Имена папок и файлов на Диске не продублированы.** Карточка импортирует `disk_organize`
(`_safe`, `category_for`, `industry_folder`, `_doc_names`) — иначе правила именования
разъехались бы с пайплайном и карточка показывала бы ссылки на несуществующие папки.

**Состояние прогона переигрывается из `events.jsonl`** тем же `apply()`, что и живой прогон,
а не хранится отдельным слепком — иначе история и живой экран разъезжаются по логике.

**Отмена мягкая.** На Windows прогон стартует в своей группе процессов, отмена шлёт
`CTRL_BREAK`; оркестратор ловит его как `KeyboardInterrupt`, гасит Kimi-подпроцесс и
корректно сворачивается. Через 20 с — принудительный `kill`. Уже готовые компании
остаются на Диске: повторный запуск с теми же параметрами пропустит их по резюму.

## API

| Метод | Ручка | Что делает |
|---|---|---|
| `GET` | `/api/health` | пути, найден ли оркестратор, активный прогон |
| `GET` | `/api/industries` | 21 отрасль из `source_rusprofile.INDUSTRY` (тянется подпроцессом) |
| `GET` | `/api/regions` | 85 субъектов РФ для подсказок (токены под подстрочный матч) |
| `GET` | `/api/models` | модели писателя: kimi (по умолч.), opus, sonnet |
| `GET` | `/api/rusprofile` | последний результат проверки (Chrome не поднимает) |
| `POST` | `/api/rusprofile/check` | проверить сессию (поднимает Chrome, ~1 мин) |
| `GET` | `/api/leads` | таблица: `q, industry, region, min_revenue, contacts, sort, limit, offset` |
| `GET` | `/api/leads/facets` | регионы, отрасли, файлы, счётчики |
| `GET` | `/api/leads/export.csv` | выгрузка по текущим фильтрам (UTF-8 BOM — для Excel) |
| `GET` | `/api/leads/{инн}` | карточка: профиль, контакты, деливераблы, кэш находок |
| `GET`/`POST` | `/api/runs` | журнал прогонов / запуск нового |
| `GET` | `/api/runs/{id}` | снимок: стадии по компаниям, стоимость, итог |
| `GET` | `/api/runs/{id}/events` | SSE-стрим; `?after=<seq>` догоняет пропущенное |
| `POST` | `/api/runs/{id}/cancel` | мягкая остановка |

## Данные

Своей БД нет — источник правды тот же, что у CLI: `ORQ_LEADS_DIR` (`D:\лиды`) для лидов,
`ORQ_DATA_ROOT/orq_cache` для находок дипресёрча, Яндекс Диск для деливераблов. Журнал
прогонов — `ORQ_DATA_ROOT/web_jobs/<id>/` (`meta.json` + `events.jsonl`), сносится безболезненно.

## Переезд в Docker

Конфиг весь через env (`ORQ_DATA_ROOT`, `ORQ_LEADS_DIR`, `ORQ_REPO_ROOT`, `ORQ_PYTHON`,
`ORQ_DISK_BASE`) — хардкод-путей в коде нет. В контейнере API поднимается рядом с текущим
ENTRYPOINT; наружу его выставлять нельзя без авторизации — он запускает платные прогоны.
Отдельный риск сервера — антибот RusProfile на датацентровых IP (см. `DEPLOY_TIMEWEB.md`).
